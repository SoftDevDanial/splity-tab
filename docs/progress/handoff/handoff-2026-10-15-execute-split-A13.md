## Traps worth knowing
- RED on today's behaviour. A test that waits on a missing element times out instead of failing on its assertion. Read with one `page.evaluate` that gives null for a missing part, and assert a control's count before clicking it. Where a test passes today or fails on a first step, its RED is a stub run (put in and taken out with the Edit tool, never committed, `grep -rn STUB src/` empty after).
- Never touch the system clipboard. Every context gets `tests/browser/clipboard/recorder.js` (or `reject.js`, `missing.js`).
- Both engines' own `showModal()` focus the first focusable area in tree order (measured by A12's stub S-A12-no-sheet-focus). R59 still wants focus moved by script, and a test only proves the target with a stub that moves focus elsewhere.
- A dialog's `close` event is queued a task after the close. Do the visible state of a click close at once (as `closeByClick` in `sheet.js` does), and keep Escape's path in the `close` event.
- WebKit closes a dialog in a task after keyup (R59 (2)). Every "press Escape" waits for the close event, at most 2 s (`press_escape`). WebKit does not focus a button on a mouse click.
- Every test that runs `test_R50_the_sheet_closes_itself_when_the_window_reaches_1024_px` writes `R50-sheet-closed-at-1024.txt` into the run's folder, so every run of it makes a folder.
- Do not run a Chromium job while a full suite runs. The R30 Escape and Cancel tests are timing flakes under load.
- No shell redirection of any kind, no heredoc and no pipe after a test runner. Probe and runner scripts go in the session scratch folder with the Write tool, and test selections in an args file (`python -m pytest @<file>`). `-p no:terminal` breaks the run's options, do not use it. A12 kept the Node output with a scratch Python runner that calls `node --test "tests/**/*.test.js"` through `subprocess` and writes stdout and the exit status into a new `qa/unit/<stamp>/node-test.txt`, and compared WebKit runs by id with a scratch script that reads both `junit.xml` files.
