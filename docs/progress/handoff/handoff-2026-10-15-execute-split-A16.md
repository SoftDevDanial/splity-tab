## Traps worth knowing
- RED on today's behaviour. A test that waits on a missing element times out instead of failing on its assertion. Read with one `page.evaluate` that gives null for a missing part, and assert a control's count before clicking it.
- A dialog's `close` event is queued a task after the close. WebKit closes a dialog in a task after keyup (R59 (2)). WebKit does not focus a button, a label or a radio on a mouse click, so a test asserts focus only after a keyboard step or a script focus.
- In Chromium a dialog's own close step puts focus back on the control that opened it when the app's focus call meets an inert control, so a focus stub must move focus to a live wrong control (A13, S-A13-return-copy).
- `press_escape` watches the last open dialog.
- Never touch the system clipboard. Every context gets `tests/browser/clipboard/recorder.js` (or `reject.js`, `missing.js`).
- No shell redirection of any kind, no heredoc and no pipe after a test runner or git. Keep each pytest run's output in its run folder through a scratch runner written with the Write tool. A15's runner (`run_pytest.py`, in its own scratch folder) runs pytest with `SPLIT_EVIDENCE=1`, writes `stdout.txt` into the run folder, prints counts and failing ids from that run's `junit.xml`, and refuses `-k` (a `-k` beside node ids widens the run). Node ids in an `@file`, one per line. To know which assertion of a test failed when two read alike, read the `test_app.py:<line>: AssertionError` line of that run's `stdout.txt`.
- The full WebKit suite takes about 7 minutes, near the 10 minute foreground limit, so run it as a background job and wait on its exit notice. Do not run a Chromium job while a full suite runs.
- The session scratch folder is shared with other agents. Keep new scratch files in a folder of your own.
- Another agent works in `examples/streaks` and runs its own Chromium and WebKit jobs. Its processes are not yours.
