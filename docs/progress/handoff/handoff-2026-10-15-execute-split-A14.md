## Traps worth knowing
- RED on today's behaviour. A test that waits on a missing element times out instead of failing on its assertion. Read with one `page.evaluate` that gives null for a missing part, and assert a control's count before clicking it. Where a test passes today or fails on a first step, its RED is a stub run (put in and taken out with the Edit tool, never committed, `grep -rn STUB src/` empty after).
- In Chromium a dialog's own close step puts focus back on the control that opened it when the app's focus call meets an inert control, so a focus stub must move focus to a live wrong control (A13, S-A13-return-copy).
- `press_escape` watches the last open dialog, the one on top when P1 is over the sheet.
- Never touch the system clipboard. Every context gets `tests/browser/clipboard/recorder.js` (or `reject.js`, `missing.js`).
- A dialog's `close` event is queued a task after the close. WebKit closes a dialog in a task after keyup (R59 (2)). WebKit does not focus a button on a mouse click.
- Do not run a Chromium job while a full suite runs. No shell redirection of any kind, no heredoc and no pipe after a test runner. Scratch runner scripts go in the session scratch folder with the Write tool.
