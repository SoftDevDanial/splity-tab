# G2 Glass Console revised, round 2 notes

**File** `g2.html`, one self-contained page with inline CSS and JS and no network, started from `g.html` (left untouched). **Checks** `checks/g2/` (`check_g2.py`, `results.json` and the screenshots). Run it with `python -B checks/g2/check_g2.py`.

Everything in `g.md` still stands unless this file says otherwise.

## What changed from G
Below 1024 px People and Charges are now one header row each, folded when a bill opens, so the phone's first screen goes header, People row, Charges row, Split, then Items. The first Items field moves up 264 px on a 390 x 844 phone (from 599 to 335) and K1 shows three whole items above the strip instead of one. People opens on a new bill, and a section with an error opens on load and, when folded, says "Check" in the error colour. And every place the person reads "Shares" now reads "Splits", on every width, while the "Split" switch heading stays. The desktop page is G's, block for block (30 blocks compared in K1, K2, S7 and W2, none moved).

**What it costs.** On a phone the names and the rates are one tap away, so a person who wants to fix a rate or a name taps the row first. The rows say what is inside them (the names, the rates) so they rarely need opening, but the edit is one more tap than in G. A second cost is a new piece of copy and behaviour that G did not have, the rate error under a Charges field, which the brief's S2 on a rate needs (reading 6).

## Readings I made
1. **The summary hides while its section is open.** The fields show the same thing right under the row, so the open row is the name and the caret only. The summary keeps its place, so the row does not jump. Flagged, because the brief lists the summary as part of the row.
2. **The summary sits on the right, beside the caret**, as a value beside a label, so the eye reads "People" down the left edge with "Split" and "Items".
3. **Twelve people read "Aisyah, Ben, Chen, Person 4 and 8 more" at 390 and "Aisyah, Ben, Chen and 9 more" at 360, with no "12 people" in front.** The names say who is in the bill and "and N more" already gives the count. A count in front would push names out, which matters most at 360. "12 people" alone is the last resort, only when not even one name and "and 11 more" fit (a 20 character first name at 360).
4. **The error marker is the summary itself turned to the error colour**, with the warning icon and "Check" plus what to check. The section name stays in body text, so the row still reads as Charges.
5. **People can never be in error.** Names have no wrong value (a blank name is "Person N"), so only Charges can carry a marker.
6. **G had no rate error, so G2 adds one.** G let a rate that is not valid count as 0 without a word, as B did. The brief's "S2 on a rate" needs an error to open Charges, so G2 shows the 1.0 rulings' copy under the field, "Enter a rate from 0 to 30" for Service charge and "Enter a rate from 0 to 20" for SST, with the same red edge as a bad price. A blank rate is not an error (it counts as 0, as in 1.0). The receipt still counts a bad rate as 0, G's prototype shortcut. Flagged.
7. **S2 keeps G's shortcut (a Subtotal of `100,00`) and gains a second one, "S2 Rate error (opens Charges)"**, the K1 bill with Service charge 35. S4 already had two shortcuts, so this follows that. Flagged, because the brief adds only the K1 open shortcut.
8. **S6 stays folded, as the brief's table lists it.** S6 starts a fresh bill like S1 ("Person 1", "Person 2"), so the S1 reason for opening People applies to it too. Flagged as a question for the owner rather than changed.
9. **A section opens on load only.** Typing a bad rate happens with Charges open, and if the person then folds it the row shows "Check", it does not spring open again.
10. **Add person sits under the list on a phone**, left aligned, where the new field appears. On desktop it stays in the heading row, as in G.
11. **The two header rows and the Split row share G's hairline** with no extra gap, so they read as one short list above Items. On a phone the Split row has 12 px above it instead of 20, and the working starts 4 px under the top bar instead of 16. Items keeps G's 20 px and its hairline.
12. **On a phone the header row is the section's heading.** G's own `h2` for People and Charges is hidden there, and the People list keeps its name from it.
13. **Opening reveals, folding is instant.** The brief names the opening only, and an instant fold never leaves a half-closed section under a finger.
14. **The rate fields name their error only while it shows** (`aria-describedby` gains `svcErr` or `sstErr`). G's price and Subtotal fields keep G's fixed reference.
15. **A rate error under a half-width field breaks into two even lines** ("Enter a rate" over "from 0 to 30") with its icon on the first, instead of leaving "30" alone on the second line.
16. **On desktop the charge cells now line up from the top, with the hint dropped by a label's height.** Every block sits where G had it (asserted), and a rate error grows its own cell downward without moving the other field (Service charge and SST fields both at 274 px in S2 on a rate).
17. **The header row's focus ring is drawn 8 px wider than the row on each side**, because the row's text starts on the column edge and a ring at 2 px would touch the "C" of Charges. The button itself stays on the column edge, clear of the Prototype states tab.
18. **Tablet widths (600 to 1023 px) fold like a phone**, since G uses the phone layout there.
19. **The header row lights its summary and caret on hover only where a pointer really hovers.** A phone keeps hover on the last thing tapped, so without this a folded row would stay lit after the tap.

## Prototype shortcuts (not design decisions)
- G's two still stand. A price that is not valid is left out of the totals while its error shows, and a rate that is not valid counts as 0. The receipt is re-rendered on every keystroke.
- The section reveal measures the open height in script and animates it. A build may prefer a CSS only reveal once the target browsers support animating to `auto`.

## Suggestions (not built)
1. Open People on S6 as on S1, since S6 also starts a fresh bill with "Person 1" and "Person 2".
2. Remember which sections the person left open, for the rest of the visit.
3. When a rate is not valid, have the receipt say so rather than count it as 0, so the strip's Total never shows a figure built on a rate the person did not mean.
4. Give the price and Subtotal fields the same "name the error only while it shows" wiring as the rates.
5. Fold Items' person toggles into a one-line summary per item on a long bill (W2), so more items fit above the strip.
6. G's suggestions 2 to 5 and 7 still stand (drag the strip, count in the Items heading, count the total up, a single-token glow, a split in the One person picker). G's 1 is answered by the owner ("That looks good already") and G's 6 is now built.

## Skills applied
`taste-skill` gave the design read (unchanged from G), one accent kept to one meaning, the button and form contrast checks, labels above fields with errors below, Phosphor icons only, no long dashes, motion only where it answers a tap and off under reduced motion, and the copy audit for every renamed string. `frontend-design` gave the restraint (the header rows are plain rows on G's hairlines, no new surface or colour), plain copy that says what to do ("Check service charge"), and a screenshot critique that caught the bold summary, the orphaned "30" and the cramped focus ring. React, Tailwind, Motion and web fonts are not used, as the brief forbids them.
